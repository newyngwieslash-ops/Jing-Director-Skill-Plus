# 4.4 项目级角色视觉标识规范

## 目的与范围

空间图的颜色用来追踪**人物身份**，不是服装色、阵营、情绪、剧情重要性或审核状态。本规范适用于每场总览、每镜首站位、末站位、走位、对应SVG/PNG及设计板；不改变合同的原镜、人物数量、台词、动作或时长。

4.3已经让同一空间规格的 `cast[id].color` 共用色源，但只检查六位十六进制颜色。旧展厅示例除男孩外九人同蓝，P编号又按场景人员顺序产生。因此“图件和人数齐全”不等于“视觉标识足够清楚”。4.4将项目级登记与一致性作为独立闸口，不能靠临时换几种颜色代替。

## 文件契约与调用

登记表顶层及人物记录只接受所列字段，变更原因/批准记录另存，不把未定义的批准字段加进表中。登记表独立于人物来源roster；roster回答“应有谁”，登记表回答“怎样稳定识别他”。不得用颜色登记补造原文没有的人物。

`identity-registry.json` 使用以下结构（仅演示字段；项目ID及角色须取真实项目值）：

```json
{
  "schema_version": "character-identity-1",
  "project_id": "demo-project",
  "revision": 1,
  "characters": [
    {"character_id": "A", "short_code": "C01", "color": "#0072B2", "marker_shape": "circle", "path_style": "solid"},
    {"character_id": "B", "short_code": "C02", "color": "#D55E00", "marker_shape": "square", "path_style": "dashed"}
  ]
}
```

- `revision` 为1至2147483647的整数，不接受布尔值；`character_id` 与空间cast/人物roster对应。
- `short_code` 为1—8位大写字母/数字，必须以字母开头，格式 `[A-Z][A-Z0-9]{0,7}`；在项目内唯一。
- `marker_shape` 支持 `circle`、`square`、`diamond`、`triangle`。
- `path_style` 支持 `solid`、`dashed`、`dotted`。
- `color` 为六位十六进制 `#RRGGBB`。以上颜色是字段示例，不是经过认证的万能色板。
- `blocking-spec.json` 新增 `identity_binding`，含 `project_id`、`revision`、`registry_sha256`。这里摘要使用 `director_core.digest(登记表JSON对象)`，即规范JSON摘要；不是文件原始字节摘要。
- `cast` 原有 `id/name/color` 保留；`color` 必须与登记完全一致（包括十六进制字母大小写），不能逐镜自行覆盖。

生成时显式提供 `--identity-registry 项目/identity-registry.json`；Python调用 `validate_blocking(..., identity_registry=登记表对象)` 或 `build(..., identity_registry=登记表对象)`。完整命令见 [空间交付](BLOCKING_COMPLETE.zh-CN.md)。缺登记不得继续严格出图。

设计板的 `blocking_bundle` 同时绑定两个项目文件：

```text
manifest_path                  图包manifest项目内相对路径
manifest_sha256                manifest文件原始字节SHA256
identity_registry_path         项目当前登记表的项目内相对路径
identity_registry_sha256       当前登记表文件原始字节SHA256
```

此处两个摘要是**文件字节摘要**，与blocking规格里的规范JSON摘要不可混用。登记表只调整空白也会改变字节摘要，因此更新设计板绑定时必须使用当前实际文件；不要手写一个“看起来像哈希”的值。项目当前登记表必须位于图包目录之外，不能将图包内部的旧快照冒充当前登记。图包保存的登记快照与当前登记须相符，否则旧图不能接入严格设计板。

## 一人一套标识

每个可辨识人物登记永久角色ID、固定短编号、身份色、辅助标记形状和路径样式。角色ID是事实关联键；短编号是图上易读索引，不能因换场、排序或新增人物而重新编号。人名相同不代表同一角色，服装改变也不代表新角色。

- 同一项目、同一登记版本内，同一角色跨全部场景、镜头与格式使用同一套标识。
- 新人物只增加新记录，不重排已有编号或自动洗牌已有颜色。
- 短编号在整个项目唯一；不能把场景局部P1当作永久身份。
- 群演逐人登记。员工1—4、游客1—2的编号是跟踪ID，不是编造姓名；群体关系另列，不把多人合成一个图标。
- 完整登记表可含本片段暂未出场人物；本片段实际人物不得缺项。不能从当前镜头人员顺序重新生成一份“项目表”。

## 身份与状态分离

| 信息 | 表达规则 |
|---|---|
| 人物身份 | 固定颜色、短编号与辅助符号 |
| 首位 / 末位 | E / X文字及实心 / 空心样式，身份色不变 |
| 首末重合 | E=X，不能画成两个人或漏掉末状态 |
| 画外人物 | OFF及专用状态描边；仍保留人物身份和位置 |
| 走位 | 同角色色的带方向路径，附路径编号与时间依据 |
| 原地不动 | 明示原地；不得省略角色或冒充缺路径 |
| 待审 / 错误 | 独立状态文字或警告标记，不把人物临时染红 |
| 地标 / 机位 | 独立命名与中性视觉层级，不占用人物身份 |

辅助形状和路径样式是身份冗余，首末空心、OFF等是状态编码，两者不得相互替代或覆盖。注册样式必须是真正画出的样式，不能只写在JSON里。

## 同场区分与配色

同场人物优先使用可区分颜色；不强求整部作品数百人每人独占一个色值，避免产生大量肉眼难辨的近似色。重复颜色必须仍有足够清晰的辅助身份标识，不能只靠拥挤图中细小的姓名勉强区分。

- 同场人物的颜色与marker_shape均相同即阻断，即使path_style不同也不能豁免：首位、末位和静止人物可能没有路线可供区分。换一个短编号也不是忽略该视觉冲突的理由。
- 接近色、低对比、与场地或机位混淆等情况应提出警告并进入视觉复核。数值检查只能筛查风险，不等于认证可辨识。
- 主要人物、群演、画内与画外人物均遵守登记，不因“配角”而免除辨认责任。
- 不用透明度、光照、选中高亮偷偷改变基础身份色。必要强调放在额外外框或说明层。
- 文本优先使用深色，旁配人物色块/符号；不要把浅黄、浅青直接用作白底小字。
- SVG与PNG共用角色映射、色值和绘图定义；抗锯齿及字体差异可能造成像素差异，不要求跨格式逐像素相等。

## 版本、证据与变更

项目登记表独立保管，并通过明确的项目身份、版本与内容摘要绑定空间规格、生成清单和设计板。设计板应与项目当前登记表核对，不能只验证旧图包内部“彼此一致”。旧图包自洽并不证明它仍是当前版本。

合法改色或改编号也是视觉修订：记录变更原因和影响角色，更新登记版本，重生成受影响图件、清单与设计板，并重新做视觉审核。旧审核只对应原始输入和原图摘要，不得复制为新版本“已通过”。工具不会伪造用户批准，也不能仅凭本次JSON证明完整历史从未被改写。

## 校验分层

**阻断项：** 缺少必需登记；人物未登记；非法字段或样式；重复角色ID或短编号；空间规格与登记表不一致；同场相同颜色且相同标记形状的身份组合（不同路径样式不能豁免）；图包或设计板绑定过期登记；图例/图件关联元数据与角色映射不符；既有漏场、漏镜、漏角色及图件摘要错误。

**人工复核项：** 近似色、拥挤、文字或路径遮挡、最终缩放后的编号/形状可辨识、灰度与常见色觉差异下的冗余是否有效、艺术调度与实际场地合理性。程序通过不是色觉无障碍认证，也不代表摄影可执行或影片验证通过。

没有登记的历史图可以保留追溯，但不得冒充4.4完整空间交付。若为兼容查看提供非严格路径，必须明确缺项，不得绕过严格输出或严格设计板验收。

## 实现闸口与风险提示

- `IDENTITY_REQUIRED`：缺必需登记；`IDENTITY_CHARACTER_MISSING`：实际人物未登记。
- `IDENTITY_SHORT_CODE`、`IDENTITY_COLOR`、`IDENTITY_SHAPE`、`IDENTITY_PATH_STYLE`：非法或冲突字段；`IDENTITY_COLOR_MISMATCH`：cast与登记颜色不一致。
- `IDENTITY_BINDING`：规格绑定与当前登记不符；`IDENTITY_VISUAL_COLLISION`：同场同色同形。
- `IDENTITY_SHARED_COLOR`：同色但形状不同，允许生成但应看图复核。
- `IDENTITY_NEAR_COLOR`：RGB距离小于实现阈值0.16的工程启发式预警，不是色觉模拟或感知色差认证。
- `IDENTITY_LOW_CONTRAST`：对指定白/浅色背景的对比筛查低于3:1。此为图标风险筛查阈值，不等于整图文字可读性或无障碍合规证明。

登记表最多10000名人物，每场最多500人，构建中的成对检查最多100000对；超限阻断，而不是跳过检查。实际发布清单使用schema1.2，包含登记快照文件引用、规范摘要、身份绑定与图例映射。当前空间输出不再生成旧场景聚合positions/movement SVG，避免旧渲染路径与新身份规则分叉；历史文件仅保留追溯，不能混入新清单。

## 视觉验收清单

1. 逐镜对照合同、独立人物roster、项目标识表及图例，身份与人数均一致。
2. 检查同一角色跨场和跨镜时短编号、颜色、形状、路径样式未漂移。
3. 查看实际PNG，并核对SVG的同源映射；不能只看文件名或JSON存在。
4. 在最终设计板尺寸检查图例、编号、首末状态、路径箭头和时间，不仅看原始大图。
5. 多人同场、画外人物、静止人物、首末重合和无人空镜分别检查。
6. 更换登记版本、篡改色值或删除登记后，严格交付应失败；重生成前不能复用旧审核。
7. 保存实际查看对象及发现的问题；未查看的图不能写“看图通过”。

本版示例覆盖范围与最终测试/逐图检查结果以 `docs/TEST_REPORT.md` 为准；不能把示例通过扩展成尚未提供的完整真实剧本已齐备。
