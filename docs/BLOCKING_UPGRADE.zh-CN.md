# 4.1.0：吸收film-blocking的优势

用户附件film-blocking-v1.0.zip具备俯视站位、轨迹、固定地点和角色、机位及Three.js预演。原图把站位与轨迹叠加，默认只处理单地点2–4镜；并未自动覆盖每场景和每原镜。

旧统一版4.0具有导演合同、文字入出态和连续性检查，但没有专用双图渲染器与逐场图审清单。两者能力互补，适合吸收空间表达层。

## 吸收与增强

| 功能 | 4.1实现 |
|---|---|
| 地点布局与稳定角色标记 | location单一几何定义；scene与location分离；角色沿用已有ID |
| 站位、走位、朝向和机位 | 每场景两类独立SVG，每原镜首末态及带时间路线 |
| 原文与动作关联 | Contract哈希、源镜号/时长、真实原文引用及beat范围 |
| 场景覆盖 | 给定合同全部场景、全部镜头必须覆盖；静止/无人不省略 |
| 跨镜连续性 | 前exit→后entry、路径首尾/链、角色及时间检查，不用teleport自由绕过 |
| 审核 | 结构、剧情关联、连续性和实看图分开；每项保留证据和文件哈希 |
| 变更传播 | 改路径影响相邻镜，改地点影响共享该地点的全部场次 |

附件原校验器把约9.9米无路径跳位仅作为警告；不能识别路径未从前位置开始，也允许未在cast登记的角色。4.1不沿用这些宽松条件。剧情语义与真实图像一致性仍不能靠坐标程序自动证明。

## Ponytail取舍

不直接复制整套技能或新增第二个活动入口。新增一个标准库模块和配套测试/规范/小示例；继续复用原合同及安装器。暂不引入Three.js、CDN、matplotlib、3D人物模型或照片重建。只要用户需要站位和走位，SVG足以明确动作，不需要额外网络服务。

附件HTML并非完全离线，且0度朝向默认值、3D曲线路径与2D折线路径存在行为差异；故不原样接入预演。将来真正需要3D时间预演时再单独实现，并保证其轨迹与核验过的2D数据一致。

附件无明确许可声明，本次采用其设计思路，独立实现绘图与校验；未分发其源代码/图片/完整技能。用户指定附件的来源记录保留在THIRD_PARTY_NOTICES.md，不添加额外授权宣称。

现有schema3.0.0、模型编译算法不变。新增blocking侧文件schema1.0，空间模块最初引入于4.1.0；当前包安装名为jingstudio。
