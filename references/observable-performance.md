# 可观察表演卡：动作有来源，真实感需看片

每个角色每个行为单元独立写，沿用固定character_id和原shot_id。下面是写作模板，不是可直接导入合同的JSON。

| 字段 | 写法与边界 |
|---|---|
| 来源/范围 | 场镜、来源行/段、原文、起止时段、角色ID；未知不能伪造 |
| 任务 | 角色正在完成什么可见任务；“悲伤/紧张”不是任务 |
| 注意对象 | 具体已存在的人/物/声源；不能凭空引入对象 |
| 触发 | 来源中哪次话语/动作/声响使其开始；没有则记未规定 |
| 主动作 | 保留源中动作及顺序；力度/速度等为提议时显式标注 |
| 重心/支撑 | 哪个支撑点承重、身体如何保持平衡；源未写则为实现推断，不冒称原文 |
| 接触/反馈 | 已有手物接触、受力反馈或无接触；动作与声响的因果 |
| 终态 | 源中动作完成后的姿态、位置、持物；衔接该镜exit |
| 不可添加 | 未写的回头、掉泪、摔倒、递物、视线交换、反应镜等 |
| 证据/状态 | 来源事实/导演推断/批准/实际视频观察分别列；未验证不得称自然 |

示例（仅方法演示，不是真实项目源）：假设原文是“甲把杯子放回桌上”。任务=放回杯；注意对象=桌上放置区；主动作=放回；终态=杯在桌上。哪只手、具体位置、承重细节属于未给定实现信息，应与已批准持物/站位核对后标推断。不能扩写成“颤抖着放下、含泪回头”。源没有声音时，杯桌接触拟音也应标声音设计建议。

镜内时序以已有temporal beats/关键帧为准。可观察细化不是新增时间；不能把一个连续动作无端拆镜或把动作完成条件删掉来迎合模型。输出表演卡后先做保真对照；真实视频出来后再逐时段看接触、重心、终态与相邻镜，文本评分不能代替视频审核。
