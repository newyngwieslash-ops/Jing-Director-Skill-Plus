# 项目记忆、版本与局部修复

本包不包含常驻Agent记忆服务。Codex按本协议读取/写入项目目录中的普通文件；未真实写入和重读，不得宣称状态已保存。

## 恢复

定位用户授权项目根目录，读project-state、当前源快照、当前合同、批准记录与本次镜头相关前后态。校验source_sha256/contract_sha256，不单凭“最新文件名”决定当前批准版本。没有状态文件则从真实材料建立首版并明确来源；不要假设包内镜9示例就是用户生产文件。

记录用户批准的范围、原话摘要与时间，区分“同意拍法”和“看图通过”。context压缩后若只剩摘要，重新读取相关真实文件和当前必要方法文档。

## 依赖与失效

依赖顺序：源/用户锁定 → Contract → 单帧生成任务 → 图像 → 人审板 → 模型prompt+manifest → 视频。
角色图更换只影响引用它的关键帧和生成任务；镜尾姿势修改至少影响本镜尾图、下一镜首图和对应模型包；摄影轴变化还需检查同场相关切点。对失效成果标stale，不删除或覆盖已批准版本。

本版`continuity`输出显式邻接图，但不提供后台自动依赖计算器。Agent必须根据reference_asset_ids、shot_ids与邻接边判断影响范围，记录到project-state.invalidated_artifacts；不要声称存在未实现的自动DAG调度。

## 修复策略

固定原镜号与来源span，另存Contract修订版。只修用户指出的域，例如“气球绳接手腕”，不要顺便改衣服或镜头角度。保持无关用户修改。必要时重新生成单帧，不必重新生成整张板。

脚本默认拒绝覆盖；只有用户授权替换当前工作版本时使用`--overwrite`。对源文件永远保留原件。失败输出继续保留，报告失败原因和下一项验证任务，不能把状态手填approved作为解决方案。

## 白模与动态片的真实证据

只有实际输出previs视频才能填写渲染回执；只有实际调用视频工具并拿到成片，才能写模型任务ID/实际片长。静态审图通过不使review.video自动升级。
