# 原工作流第一至六步（保留版）

仅新剧本全流程使用。已有 Excel 进入导演增强时，不要求重做已确认成果。
本文件中的路径从 Skill 根目录解析。现行优先规则见 SKILL.md。全部暂停点按用户选择的逐步审阅/自主批处理模式执行；缺少图片时可以完成文本规划和Excel，但保持视觉生产未就绪。

统一版4.1起，完整导演分镜任务还须逐场交付角色站位图、走位图并审核。第4.5步拟定空间关系，第5步镜表明确后形成合同及绑定空间数据；第6步Excel完成后按 `references/scene-blocking.md` 出实际双图与审核记录。只有用户明确仅要表格/文字时才在表格完成处停止。示意图由代码绘制，无生图API也可交付。

### 第一步：导演定调

**输入：** 剧本（或整理后的文本）
**输出：** 导演定调方案

1. 分析剧本，从六个维度（情绪基调、类型片、动作与对抗、题材关系、叙事形式、社会视角）判断涉及哪些维度
2. 从各相关维度的导演风格模板库中，提取2-3个有差异的导演方向，每个方向融合多位导演的具体方法论
3. 通过分轮引导式提问确认用户倾向——先锁定情绪和类型大方向，再细化视听偏好，最后确认题材/形式/社会维度
4. 输出完整的导演定调方案（含维度参考、融合方案和七项视听决策）

**读取：** `references/core-methodology.md` 第二节 + 根据维度判断读取对应的 `genre-[A-F]-*.md` 文件（通常2-3个）

**自检清单：**
- [ ] 是否从多个维度综合考量（而非只选一个类型）？
- [ ] 每个方向是否引用了具体导演的具体方法论（而非空泛描述）？
- [ ] 融合方案是否明确了主导参考和局部借鉴？
- [ ] 引导式提问是否自然（不是把维度列表或导演菜单给用户看）？
- [ ] 导演定调的七项视听决策是否全部明确？
- [ ] 意象体系是否已规划（视觉母题、意象方向、需突出强化的视觉元素）？

→ 暂停，等待 [通过 / 修改 / 自检]

---

### 第二步：节奏规划

**输入：** 确认后的导演定调 + 剧本
**输出：** 场景级节奏规划（含镜头组划分）

1. 逐场标注双轨节奏（情节松紧 + 情感轻重）
2. 叠加导演执行层信息（镜头密度、景别重心、预估时长、转场策略）
3. **划分镜头组**——标注每场戏内哪些叙事目的由一组紧密相接的镜头共同完成（蒙太奇组/递进组/因果组/对比组），并预估每组的镜数和时长
4. 输出全片节奏波浪图（导演版）
5. 做节奏诊断

**读取：** `references/core-methodology.md` 第三节（含镜头组方法论）+ `references/storyboard-format.md` 时长估算参考

**自检清单：**
- [ ] 每场戏是否都有双轨节奏标注？
- [ ] 镜头组划分是否合理？（组内镜头逻辑是否紧密？）
- [ ] 镜头组的预估时长是否符合时长参考数据？
- [ ] 全片是否有足够的节奏起伏？（避免长时间单一强度）
- [ ] 高潮段是否有足够的铺垫时间和差异化的镜头策略？
- [ ] 呼吸场景是否保留？
- [ ] 预估总时长是否在目标范围内？

→ 暂停，等待 [通过 / 修改 / 自检]

---

### 第三步：剧本微调

**输入：** 确认后的节奏规划 + 原剧本
**输出：** 微调后的剧本

1. **视听化修正（前置）：** 只修改无法被摄影机拍到的内容（"角色觉得""角色感受到"等）。特效、内心独白、字幕等正常视听语言不动。
2. **四焦点微调：**
   - **表演节奏**：拆分或合并角色动作，延长或缩短段落节奏
   - **台词对白**：延长/缩短/改写内容，调整断句，匹配节奏和角色状态
   - **画面内容**：增删视觉细节，提升画面质感（如增加细节表演、删除多余画面）
   - **意象落地**：将导演定调中已规划的意象体系（母题、环境意象）具体植入剧本的相应位置
3. 所有微调按焦点分组，用对比格式输出（原文 → 微调 + 理由）
4. 如果剧本无需微调，明确告知并说明原因

**读取：** `references/core-methodology.md` 第四节

**自检清单：**
- [ ] 视听化修正是否只改了"不可拍"的内容？（没有把特效/旁白/字幕当作问题来改）
- [ ] 表演节奏的拆分/合并是否服务于节奏规划中该场景的目标节奏？
- [ ] 台词微调是否保持了角色的说话习惯和口语化？
- [ ] 新增的画面细节是否可以被摄影机拍到？
- [ ] 意象落地是否与导演定调中的意象体系一致？
- [ ] 是否遵守了微调边界（不改核心戏剧动作和人物弧光方向）？

→ 暂停，等待 [通过 / 修改 / 自检]

---

### 第四步：提取角色以保持全局一致性

**输入：** 微调后的剧本（或确认无需微调的原剧本）+ 导演定调 + 节奏规划 + 已有角色/美术设定（如有）
**输出：** `character_bible.json` 角色全局档案 + 主要/常驻角色三视图参考图 + 三视图生成提示词与资产索引

1. 从完整剧本、场景标题、动作描写、对白署名、旁白/声音提示中提取全部角色：主角、配角、功能角色、群像角色、COS/伪装身份、被提及但会影响画面的角色。
2. 做角色去重与名称对齐：移除括号后缀，合并别名/称谓/英文名，为每个角色生成稳定 `id`，后续所有分镜、图片、视频提示词都必须引用同一 `id`。
3. 输出结构化 `character_bible.json`。每个角色至少包含：`id`、`name`、`aliases`、`era_background`、`occupation`、`role_description`、`visual_traits`、`key_visual_traits`、`dialogue_traits`、`wardrobe`、`performance_traits`、`continuity_rules`、`negative_prompts`、`reference_assets`、`appears_in`。
4. **提取角色后，先生成各角色三视图参考图。** 为主角、常驻配角、跨场景复现角色生成并执行 `triple_view_prompt` / `triple_view_prompt_json`：强制同一个真实人类演员或同一角色设计、正面/90度侧面/背面、同一服装妆发、同一体型比例、电影真人质感或项目既定风格、16:9、左上角角色名。提示词结构可参考 JSON 式图片模板，但布局必须改为三视图角色设定图，而不是多姿势写真合集。
5. 将每个角色的三视图生成结果写回 `character_bible.json.reference_assets`，至少记录 `triple_view_prompt`、`triple_view_prompt_json`、`triple_view_image_path` 或 `triple_view_image_id`、生成状态和需要用户确认的问题。缺少三视图的主要/常驻角色需列为待生成；允许继续第五步文本草稿，不得标记视觉一致性已通过。
6. **为高一致性执行故事板补齐强参考资产。** 主要/常驻角色除三视图外，还必须尽量生成或登记 `identity_sheet_path`、`face_closeup_path`、`wardrobe_sheet_paths[scene_id]`、`identity_anchors`、`identity_forbidden_drift`。三视图是基础参考，不等同于长篇执行故事板的一致性充分条件。
7. 如果当前环境不能直接生成图片，必须输出可直接用于 GPT image 2 或同类图像模型的结构化三视图、脸部近景、场景服装图提示词，并记录缺图及生成条件；可继续分镜文本草稿，实际视觉生产须待参考图就绪。
8. 如果后续分镜拆解时出现 `character_bible.json` 未登记的新角色，必须先回到本步骤补录角色，并先生成该角色三视图/脸部近景/当前场景服装参考图，再继续视觉生成；文本分镜可先标记待参考图的草稿。
9. 后续生成图片、视频提示词、执行故事板图片时，必须同时提交/引用 `character_bible.json`；主要/常驻角色已生成的三视图、脸部近景、服装图必须作为角色视觉锚点一并提交。只在提示词中写“参考某角色”而未实际提交参考图时，不得声称角色一致性已确认。

**读取：** `references/character-consistency-format.md` + `references/core-methodology.md` 第四节

**自检清单：**
- [ ] 剧本中所有有名角色、功能角色、群像模板和伪装/COS身份是否都已登记？
- [ ] 同一角色的别名、称谓、英文名是否已合并到同一个稳定 `id`？
- [ ] `visual_traits` 是否足够具体，可直接支撑 AI 生图（年龄、脸型、发型、服装、体型、气质）？
- [ ] `key_visual_traits` 是否提炼出3-5个不可改变的视觉锚点？
- [ ] `dialogue_traits` 和 `performance_traits` 是否能约束后续对白/表演一致性？
- [ ] 每个主角/常驻配角是否已生成三视图参考图，并把图片路径/结果编号写入 `reference_assets`？
- [ ] 三视图是否包含正面、90度侧面、背面，且脸、年龄、体型、发型、服装轮廓、道具和色彩保持一致？
- [ ] 主要/常驻角色是否已补齐 `identity_sheet_path`、`face_closeup_path`、当前场景 `wardrobe_sheet_paths`、`identity_anchors`、`identity_forbidden_drift`？
- [ ] 是否明确区分“已有参考图”与“实际作为 GPT image 2 输入提交过参考图”？
- [ ] 是否明确禁止后续步骤凭空新增角色外观？

→ 暂停，等待 [通过 / 修改 / 自检]

### 第四点五步：场景一致性资产

**输入：** 已确认的导演定调 + 场景/地点清单 + `art_style_bible.json`（如有）+ 角色出场关系
**输出：** `scene_bible.json` 场景全局档案 + 反复出现/视觉复杂场景的 scene plate / 场景图参考资产

1. 为所有反复出现、视觉复杂、会进入执行故事板图片的地点建立稳定 `scene_id`，不得在后续临时改名或重新发明空间。
2. 输出 `scene_bible.json`。每个场景至少包含：`scene_id`、`name`、`scene_aliases`、`era_background`、`geography_layout`、`lighting_lock`、`palette_lock`、`prop_locks`、`weather_time_lock`、`negative_prompts`、`reference_assets`。
3. 为重要场景生成或登记 `canonical_scene_plate_path`：场景图应尽量不含主要角色，重点锁定空间结构、光线、色彩、核心道具和气候状态。
4. 为同一地点的不同状态生成 `scene_variant_paths`，例如宴会前/宴会后、洪水前/洪水后、白天/夜晚，但每个变体必须继承同一 `scene_id`。
5. 后续执行故事板和 Seedance 2 manifest 必须使用稳定 `@scene_<scene_id>` 与 `@scene_<scene_id>_plate` 引用；缺少场景图时可先输出提示词，但不得标记场景一致性已确认。

**读取：** `references/scene-consistency-format.md` + `references/core-methodology.md` 第二节

**自检清单：**
- [ ] 是否为反复出现/视觉复杂场景建立了稳定 `scene_id`？
- [ ] 是否生成或登记了 `canonical_scene_plate_path`？
- [ ] 场景的空间关系、光线、色彩、核心道具、天气/时间是否已锁定？
- [ ] 后续执行故事板是否能通过 `@scene_<scene_id>_plate` 实际提交场景参考图？
- [ ] 缺少 scene plate 时是否标记阻塞或未验证，而不是确认一致性？

→ 暂停，等待 [通过 / 修改 / 自检]

---

### 第五步：分镜拆解

**输入：** 微调后的剧本（或确认无需微调的原剧本）+ `character_bible.json` + `scene_bible.json`（如需要高一致性执行故事板）+ 已确认角色三视图/脸部近景/服装参考图 + 导演定调 + 节奏规划
**输出：** Markdown格式的分镜表；当用户要求AI视频生成、图生视频、文生视频、视频提示词或长期角色/美术一致性时，同时输出「视频提示词」字段。

1. 逐场进行叙事目的分析（参见 `core-methodology.md` 第一节）
2. 根据叙事目的、导演定调、节奏规划，逐镜头拆解
3. 每个镜头的出场人物必须来自 `character_bible.json`，并优先使用稳定 `id` + 中文名；禁止临时改写角色外观
4. 生成九列标准格式的分镜表（Markdown预览版）
5. 如用户要求视频生产，按 `references/video-prompt-format.md` 为每个镜头生成独立视频提示词；提示词必须严格使用固定字段模板，不写成普通单句prompt，并注入当前镜头角色的 `visual_traits` / `key_visual_traits`
6. 按场景/段落分批输出（不一次性生成全片）

**读取：** `references/core-methodology.md` 第一节（叙事目的）+ `references/shot-design.md`（动作-反应结构、切镜连接、对白处理、Double Check）+ `references/storyboard-format.md` + `references/character-consistency-format.md`；如需视频提示词，同时读取 `references/video-prompt-format.md`

**分批输出规则：**
- 短片（5分钟以内）：可以一次性输出，或按场景分2-3批
- 中片（5-15分钟）：按场景或段落分3-5批
- 长内容（15分钟以上）：每次输出一个段落/序列

每批输出后暂停确认。

**自检清单：**
- [ ] 每个镜头是否有叙事目的？
- [ ] 叙事目的是否具体到视听手段（而非空泛概括）？
- [ ] 画面内容是否只包含可见元素？
- [ ] 时长估算是否合理？（总时长不超过目标时长）
- [ ] 相邻镜头的景别/角度连接是否有视觉逻辑？（参见切镜连接逻辑）
- [ ] 场景转换处是否有合适的连接方式？
- [ ] 对白场景的处理方式是否多样化？（不是所有对话都用正面中景正反打）
- [ ] 景别和摄影角度的变化是否有节奏感？
- [ ] 声音列是否完整（对白+音效+配乐）？
- [ ] 导演定调中规划的意象体系是否在分镜中落地？
- [ ] 每个镜头的出场人物是否都能在 `character_bible.json` 中找到稳定 `id`？
- [ ] 如输出视频提示词，每个镜头是否都包含固定模板字段：分镜、时代、时间、场景、人物、画面、Shot、对白、镜头移动、音效/音乐、电影风格？
- [ ] 视频提示词是否只基于当前镜头可见/可听内容、角色设定和美术设定生成，避免新增剧情事实？
- [ ] 镜头编号是否连续？
- [ ] **Double Check三层**：①导演影调一致性 ②本段节奏匹配 ③每场戏是否有约20%的出彩设计？（出彩点是否出现在叙事重心上？）

→ 每批暂停，等待 [通过 / 修改 / 自检]

---

### 第六步：输出表格

**输入：** 用户确认通过的完整Markdown分镜表
**输出：** .xlsx 文件

1. 将Markdown分镜表转换为xlsx格式
2. 如果用户要求视频生产，在原九列之后新增 `视频提示词` 列，每个镜头一条完整提示词
3. 按 `storyboard-format.md` 第五节的规范设置列宽、格式、样式
4. 输出文件供用户下载

**读取：** `references/storyboard-format.md` 第五节；如包含视频提示词，同时读取 `references/video-prompt-format.md`

→ 输出文件。完整导演任务继续完成本次全部场景站位图、走位图与审核；明确仅要表格时可在此结束。再按用户范围进入执行故事板或模型提示词阶段。
